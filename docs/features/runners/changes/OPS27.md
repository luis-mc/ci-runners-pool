Adding Linux runners on a Windows machine to the pool works end to end (R5.47, R5.27). Reasoning: R5.47 says a container runner on a Windows machine takes the pool's jobs and carries the pool label, but the plan refused every ephemeral runner of the pool scope, and the console sends exactly that for Linux on Windows, so the owner's request failed at Done. The one-pool model (the user adds runners by machine, system and count) decides it: the controller now accepts a pool-scope ephemeral request when it is the Linux container runner of a Windows machine, and stores it as a pool runner with no registration of its own (a container starts for each job). An ephemeral pool runner on any other machine is still refused with the reason. A refusal is given when the plan is made: the container backend not allowed on the machine, or no step. Add runners says so on step 1 with a link to the machine page and keeps Next disabled; a plan that has no step never reaches Review. After a failure the step strip marks the failed step and does not tick it, the message ends with a full stop, and Try again goes back to step 1 with the reason instead of repeating the same request.
