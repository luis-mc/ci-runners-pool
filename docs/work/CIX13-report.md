## Built per requirement

## Contract gaps (questions for the orchestrator) and local workarounds

1. `reconcile.Store` has no list of a run's open job ids, no job read and no steps-only write. Workaround: extra interface `reconcile.JobStore` (OpenJobs, JobRef, ApplySteps) in `reconciler.go`, implemented by the store. Fine to keep, or move into `Store` at the join.
2. `jobsdata.Writer` has no write for runner origin or steps source. Workaround: `ingest.OriginSink` (SetRunnerOrigin, SetStepsSource), implemented by `store.InsightsJobsStore`. Wiring (CIX18): pass `store.InsightsJobs()` as `ingest.Config.Origins`, `reconcile.NewClassifier(runners)` as `Classify`; after `OnJob` of a workflow_job webhook call `github.ParseRunnerFields(body)` then `Recorder.OnRunner`. Also CIX18: build `reconcile.New(Config{...})`, run `Pass` every `reconcile.PassEvery`, call `JobCompleted` when a job completes and `Watch` while a Job page is open, and `reconcile.Runners` over the runner registry.
3. No column for the lost reason. Workaround: reason stored in `jobs.wait_text` with result `lost`.
4. `github.Job` (webhook) carries no runner group. Workaround: `ParseRunnerFields` (above).
5. `internal/store/sqlcgen/db.go` is regenerated by `go tool task codegen:sql` and is committed here because the new queries need it; regenerate at the join, do not merge by hand.
6. Spec section 9: R5.39 row names `JobPage.test.tsx` (CIX19, web); not touched here.
