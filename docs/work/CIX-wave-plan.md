# CIX wave plan: CI run insights

Branch only (docs/work never reaches the default branch). Spec: `docs/features/ci-run-insights/spec.md`. Contract on `CIX-integration` (CIX8): migration 00030, `internal/store/queries/insights_*.sql` and their sqlc code, the `/api/v1/insights/*` routes (501 stubs in `internal/api/stubs_insights.go`), agent link protocol version 4 (`JobResourceSamples`), and the Go interfaces under `internal/insights/`, `internal/agent/jobsample/`, `internal/jobsdata/reconcile/`. Task ids CIX7 (observability note) and CIX8 (this contract) are used; the wave takes CIX9 to CIX20.

## Rules for every agent

- Branch `<task-id>-<slug>` from `CIX-integration`. Own only the files in your row; a file not listed is read-only for you.
- Do not change the migration, `openapi.yaml`, `agent.proto` or the interfaces of `internal/insights*/<family>.go` (the contract). A contract gap goes in your report as a question for the orchestrator; work around it with a local type until answered.
- You may add queries to your own `internal/store/queries/insights_<family>.sql` file only. Run `go tool task codegen:sql`; the shared generated files (`internal/store/sqlcgen/db.go`, `models.go`) are regenerated at the join, never merged by hand.
- Analysers read jobs through `insights.JobSource` and test with fakes; CIX9 builds the store implementation.
- Test only what you touch; Go tests next to the code; web tests with Vitest. Change notes with `docs_fold.py note --doc features/ci-run-insights --task <id>`; turn your requirements' "planned:" rows of spec section 9 into real paths.
- Never store or log a secret; logs and reports pass `internal/redact` (R5.4, R6.5).
